# Interview Q&A

**Why claims analytics?** It combines healthcare data, SQL, data quality, anomaly analysis and reporting.

**Why synthetic?** It avoids real-patient privacy issues while allowing controlled, non-uniform patterns.

**How did you avoid equal weighting?** Patient utilization, provider activity, payer mix, diagnosis/procedure frequency, facility size and claim amounts all use different distributions.

**Which SQL concepts?** Joins, CTEs, GROUP BY, HAVING, CASE, LAG, ROW_NUMBER, window functions, peer benchmarks and reconciliation.

**How are anomalies detected?** P99 high-value claims, provider weekly volume spikes, financial exceptions and missing provider attribution.

**Does an anomaly mean fraud?** No. It means review the pattern and context.

**What would you automate?** Scheduled ingestion, quality checks, exception tables, anomaly scoring and Power BI refresh.

**What would you improve?** More robust peer groups, production claims lifecycle fields, monitoring alerts, role-based security and model governance.
